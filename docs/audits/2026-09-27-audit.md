# Whole-application audit — MetaClassify (api_v3) 4.0.0

Date: 2026-09-27 · Level: **Deep** on the serving and import surface (auth, request handling,
archive import, skops loading, sharing, the new `app/metadata/` package, the admin UI's
`innerHTML` paths), **Standard** across all twelve dimensions. Baseline for comparison:
[2026-09-20-audit.md](2026-09-20-audit.md) (overall 77, *Conditional*), whose 45 findings were
closed or refuted by 2026-09-27 and released as 4.0.0 (`3506c83`).

## 1. Executive summary

One week and one release after the last audit, MetaClassify is in markedly better shape:
**overall 85 (was 77)**, every 🔴 and 🟠 from the previous report closed, coverage measured at
95 % against a floor of 92, both lock files clean under `pip-audit`, and a release pipeline
that is now exercised end to end. Confidentiality and integrity were re-verified from the
source rather than carried over: the archive import is allowlisted by exact member name, the
only skops load in the app trusts an empty explicit list, both API keys compare in constant
time, share ids carry 96 bits, and none of the 44 places where server data meets `innerHTML`
skips `esc()`. **The top risk is new and sits in the feature 4.0.0 introduced:** `/metadata`
spends super-linear time on a single long line, inside a third-party sentence splitter
(`pysbd`), so one request at the documented caps costs on the order of five CPU-minutes in a
single-worker process, and a readonly key is enough to send it (S-2). The second is a guard
that data-prep has and this app does not: `APIV3_AUTH_ENABLED=false` makes every caller an
admin on whatever interface the process is reachable from (S-1). Third, one test fails on a
slow machine and not on a fast one (T-1). **Most important action: bound the length of the
line handed to `pysbd`, with a scaling test at the 100,000-character cap** — the project's own
rule for every new pattern, applied to a dependency's pattern.

## 2. Overview

**Stack:** Python 3.11/3.12 · FastAPI + uvicorn (single worker by design) · scikit-learn
(sparse float32 TF-IDF word+char, OneVsRest LogisticRegression) · skops (pickle-free
persistence) · pydantic-settings · slowapi · wordfreq / pysbd / snowballstemmer for
`/metadata`. Vanilla-JS admin UI with no build step. File-based state on one volume.
Docker (digest-pinned base, hash-pinned install), a Helm chart, GitHub Actions and GitLab CI.

**Purpose:** train metadata text classifiers on CSV exports, serve predictions over REST, and
— since 4.0.0 — propose a title, a description and keywords extracted from the text itself.

**Size:** 74 app modules / 11,853 lines · 65 test files / 15,574 lines (972 tests) · 20 UI
files / 4,169 lines · 24 scripts · 17 markdown documents.

**Read:** every route's auth and rate-limit wiring (38 routes, from the built app and from the
AST of every handler); `app/security.py`, `app/lifecycle.py`, `app/model_archive.py`,
`app/model_io.py` (load path), `app/sharing.py` (minting and expiry), `app/routes/system.py`,
`app/routes/models.py` (report routes), `app/routes/metadata.py`, all of
`app/metadata/budget.py`, the sentence and reference handling in `app/metadata/textprep.py`,
the phrase patterns in `app/metadata/phrases.py`, `app/train_worker.py` (spawn path and child
entry), the coverage and CI configuration, the Dockerfile, `docker-compose.yml`, and the
chart's values. All 18 compiled patterns in `app/metadata/` and `app/markup.py` were read.
**Measured, not reasoned:** the route surface, the metadata scaling curve at three input
shapes up to the cap, a profile of the worst one, the budget truncation edges, whether the
training child writes coverage data, the OSV status of the vendored Swagger UI, and README
endpoint drift.

**Not covered:** line-by-line reading of the training pipeline (`prepare`, `deploy`,
`tuning`, `vocabulary`) beyond the complexity leads — unchanged in its hard parts since the
last audit, which verified them; the chart templates beyond what `tests/test_helm_chart.py`
now renders; a real screen-reader pass of the UI.

**Scanners:** `ruff` (project gate: clean; wider lead scan with bandit `S`, `C90`, `PERF`,
`B`: five leads, one a false positive — see M-1 and the note on S603), `mypy` (74 files,
clean), `pip-audit` on `requirements.lock` and `requirements-hashes.lock` (no known
vulnerabilities), `coverage` (95 %), OSV for `swagger-ui-dist@5.17.14` (0 advisories).

## 4. Verdict: **Conditional**

Production-ready for the deployment it is designed for — one operator, readonly keys issued
to trusted internal callers. **Condition before a readonly key is handed to anyone who might
send hostile input:** fix S-2. A single request at the documented limits (100 texts of
100,000 characters, all on one line) holds the GIL for minutes in a process that serves every
other request, and `predict_limit` allows 300 of them a minute. S-1 is a hardening condition
rather than a blocker: every shipped default is safe, and it takes an explicit
`APIV3_AUTH_ENABLED=false` plus a non-loopback exposure to open the admin API.

## 5. Top issues

```
[🟠 HIGH] Security (availability) — /metadata sentence splitting is super-linear in line length   S-2
  File:     app/metadata/textprep.py  (and the pysbd dependency it calls)
  Lines:    249–262  (split_sentences — hands pysbd one whole line per call)
  Problem:  pysbd's German abbreviation replacer runs one whole-string re.sub per abbreviation
            candidate, so the cost of a line grows with (candidates × length). Measured on
            2026-09-27, one text, generate() end to end:
              short lines   25k → 100k chars:  0.33 s → 1.25 s   (×3.8 — linear)
              prose         25k → 100k chars:  0.23 s → 2.94 s   (×12.7)
              no punctuation 25k → 100k chars: 0.33 s → 2.96 s   (×9.0)
            A profile of the 100k prose case puts 3.13 s of 3.46 s in pysbd.segment, 2.42 s of
            it in lang/deutsch.py:scan_for_replacements (1,691 calls, 27,267 re.sub runs).
  Why:      split_sentences already treats every line break as a hard boundary, which is
            exactly why the short-line shape stays linear — but nothing bounds how long one
            line may be, and the request schema admits 100,000 characters per text.
  Impact:   texts are answered independently, so a request at the caps (100 × 100k-char single
            lines, ~10 MB — under the 200 MB body limit) costs ~100 × 3 s ≈ 5 CPU-minutes
            (extrapolated from the measured per-text time). re does not release the GIL and
            the app is single-worker by design, so every prediction waits behind it. Reachable
            with a readonly key; predict_limit allows 300 such requests a minute.
  Fix:      hand pysbd bounded pieces: split a line longer than N characters (N ≈ 2–5k, far
            above any real paragraph) at the last sentence-ending punctuation before N, falling
            back to whitespace, and segment the pieces. Lines under N — every real text — are
            unchanged, which test_metadata_parity.py will confirm. Add a scaling test at the
            100,000-character cap for the prose and no-punctuation shapes, as CLAUDE.md
            requires of every new pattern. Optionally lower the per-request text count.
  Example:  for line in text.splitlines():
                for piece in _bounded(line, 4_000):   # splits only lines over the bound
                    for segment in _segmenter.segment(piece): ...

[🟡 MEDIUM] Security — auth-disabled grants admin to every caller on every interface   S-1
  File:     app/lifecycle.py ; app/security.py
  Lines:    lifecycle.py 96–97 (_check_auth_configuration returns at once when auth is off);
            security.py 23–24 (_role_for_key returns "admin" when auth is off)
  Problem:  the docs say APIV3_AUTH_ENABLED=false is for local use only; nothing enforces it.
            data-prep enforces the same rule (keyless only for loopback clients, 403 otherwise).
  Why:      the image binds 0.0.0.0 inside the container; the chart ships an ingress.
  Impact:   one environment variable plus any non-loopback exposure (a `-p 8000:8000`, the
            chart's ingress) is an unauthenticated admin API: train, delete models and
            datasets, import archives. Every shipped default is safe (compose publishes on
            127.0.0.1, the chart defaults to auth on), so this needs a misconfiguration.
  Fix:      port data-prep's `_is_loopback_client` check into require_role for the
            auth-disabled branch. Caveat to document with it: under Docker a local request
            arrives from the bridge gateway (e.g. 172.17.0.1), not loopback, so keyless mode
            stops working in a container — which data-prep already documents as intended.

[🟡 MEDIUM] Testing — the child-kill test fails on a slow machine   T-1
  File:     tests/test_train_worker.py
  Lines:    184–193  (test_a_kill_ends_the_child_at_once)
  Problem:  asserts that a whole _run — spawn an interpreter, import the app under coverage,
            start a training, kill it — finishes in under 8 seconds of wall clock.
  Why:      the budget measures the machine, not the property. The same 957 tests took 181,
            197, 261, 281 and 283 s within one hour on 2026-09-27; the test passed at the
            first three and failed at the last two, and passed 26/26 in three isolated runs.
  Impact:   a red gate that a re-run turns green teaches everyone to re-run instead of read.
  Fix:      measure what the property is about — the time from the kill request to the child's
            exit — rather than the whole run including spawn and import; or keep the wall
            clock but derive the budget from a measured spawn time in the same test.
```

## 6. All findings

### Security
- **S-2** 🟠 availability — super-linear sentence splitting on `/metadata` (top issues).
- **S-1** 🟡 auth-disabled not confined to loopback (top issues).
- Verified sound, no finding: all 38 routes carry the role their docstring states, the seven
  public ones are probes, static assets and the capability-by-token share route; the 14 routes
  without a rate limit are all cheap (`/ready` is two `is_dir()` and two `os.access()`, the
  model report routes read JSON only). Archive import refuses any member name outside a fixed
  set before a byte is written, bounds expansion by ratio *and* absolute ceiling, and deletes
  every written member on any failure. The one skops load (`model_io.py:137`) trusts an empty
  explicit list after refusing anything `get_untrusted_types` reports. The train child's argv
  is fixed and the job travels over stdin — ruff's `S603` at `train_worker.py:230` is a false
  positive. Share ids are `token_urlsafe(12)` (96 bits), clamped to 1 h – 7 d. The UI's template
  interpolations were screened (96 not visibly wrapped, narrowed to 44 that touch a data
  property): the rest are literals, numbers or helper calls, and the three that carry raw
  server strings reach the DOM through `textContent`, a download filename and the
  clipboard. The helpers were verified to escape where this audit's changes touched them
  (`metadataField`, `metadataCard`, `predictionRow`, the bulk table); the others are
  unchanged since the 2026-09-20 audit verified them.

### Logic & correctness
- No new findings. `app/metadata/budget.py` was probed on the five edges the suite never
  exercises (clause cut, word cut, one unbroken word, a break at position 0, an exact fit):
  every result stays within its budget. A line that *begins* with `", "` keeps the comma
  (`", beginnt mit…"`). The sentence splitter merges a comma-led fragment into the previous
  sentence only within one line (`textprep.py:258`, `len(sentences) > start`), so a line that
  itself opens with a comma is not repaired; cosmetic, and inherited from the source app.
