## 1. Executive summary

All three conditions of the previous *Conditional* verdict are **resolved and
test-verified**: the registry disk race is serialized (`_disk_lock` + Event-based
test), `/train/status` is sanitized (with `TrainingInputError` preserving crafted
user-facing messages), and the CV double-dip optimism is caveated in README +
docstring. On top, the full audit roadmap (Phases 2–4) landed: security headers,
rate limits on every heavy/public route, `/metrics`, digest-pinned base image,
`readOnlyRootFilesystem`, fully-hashed transitive dependency lock (verified by a
real `--require-hashes` install + clean `pip-audit` over the whole tree), the
`training.py` split, and 25 new tests (65 total, order-independent). Two new
findings emerged, one of them worth fixing soon: `run_training` builds a **fresh
`Registry` instance**, so its disk I/O does not share the singleton's lock —
currently safe only through a chain of route-level guards. Single most important
action: inject the shared registry into `run_training`.

Verdict: **Yes — production-ready** for the documented single-worker deployment.

## 5. Top issues

### AUD-1 🟠→🟡 Architecture/Correctness — training bypasses the shared registry lock
- **File:** `app/training.py` · **Line:** 120
- **Problem:** `run_training` instantiates `Registry(settings.models_dir, ...)`
  fresh, so its `_disk_lock`/`_lock` are different objects than the
  `get_registry()` singleton all routes use. The training `save()` is therefore
  **not** serialized against API-side reads/deletes/imports.
- **Why it is currently safe (verified):** `/train` refuses existing names (409),
  so the save never rmtree's a readable bundle; the tmp→rename publish is atomic;
  the singleton cold-loads new names on demand. Safety rests on this chain of
  route-level guards, not on the lock design.
- **Impact:** any future overwrite/re-train feature (or a delete racing a
  just-finished train of the same name) silently re-opens the TOCTOU class the
  disk lock was built to close.
- **Fix:** inject the registry: `run_training(..., registry: Registry)` supplied
  by the route from `get_registry()` (tests pass their own instance built from
  their Settings). Severity downgraded to 🟡 because it is not reachable today.

### AUD-2 🟡 Performance/API — `GET /datasets/{name}` reads the whole file, unthrottled
- **File:** `app/routes/datasets.py` · **Lines:** 74–75
- **Problem:** the row count is computed by iterating **every line** of the CSV;
  the endpoint is readonly-key accessible and has **no rate limit** (the recent
  limit sweep covered `analyze`/`validate`/`share` but missed this one).
- **Impact:** a readonly client can keep the single worker busy re-reading a
  200 MB file at line granularity (I/O-bound DoS pressure).
- **Fix:** add `@limiter.limit(export_limit)` like its siblings; optionally cap
  or cache the row count (e.g. `os.stat` size + estimated rows, or count once
  at import time).

### AUD-3 🟢 Maintainability — `registry.py` at the 300-line threshold
- **File:** `app/registry.py` (301 lines)
- **Problem:** two responsibilities cohabit: skops-safe bundle I/O (+ zip
  validation) and the LRU registry. At the smoke-detector threshold, not past it.
- **Fix:** when next touched, split `bundle_io.py` (read/write/validate) from the
  `Registry` class. Do not split pre-emptively.

### AUD-4 🟢 Correctness — hard stop can be overwritten by the finishing thread
- **File:** `app/jobs.py` · **Lines:** 102–105 vs 89–93
- **Problem:** `stop(hard=True)` sets status `idle` while the cooperative target
  may still run; when it finishes, the runner overwrites `idle` with `stopped`.
- **Impact:** transient status inconsistency on `/train/status`; no data damage.
  Pre-existing, unchanged.
- **Fix:** have the runner skip its final update when the state was hard-reset
  (e.g. compare a run-generation counter).

### AUD-5 🟢 Maintainability — local `import pandas as pd` inside `dataset_info`
- **File:** `app/routes/datasets.py` · **Line:** 67
- **Problem:** function-local import of a module that is a hard app dependency
  anyway; inconsistent with the codebase's top-level import style.
- **Fix:** move to module imports (pandas is already loaded via `app.data`).
