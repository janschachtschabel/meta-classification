## 1. Executive summary

api_v3 is a genuinely well-engineered, security-conscious application — no
critical (🔴) defect exists. Authentication is complete and constant-time,
deserialization is pickle-free (skops with an empty trust allowlist), uploads are
capped and staged atomically, and the registry's two-lock design and the training
job's generation-guarded state are unusually careful. The risks that remain are
**operational correctness under the intended production topology**, not broken
fundamentals. The top three: (1) the hardened Helm deployment's
`readOnlyRootFilesystem: true` has **no writable `/tmp`**, so Starlette's
multipart spooling breaks every upload over ~1 MB — the core admin workflow is
broken on the documented K8s path while the README claims it is safe; (2) a
`hard=true` training stop abandons the *status* but never stops the *thread*, and
because the restart guard is status-based, a subsequent `/train` runs a second
training concurrently — violating the single-worker invariant the whole design
rests on; (3) the rate limiter keys on `get_remote_address`, which is the reverse
proxy's IP in the shipped topology, collapsing all clients into one shared bucket
and defeating the share-id brute-force protection. **Single most important
action:** add a writable `/tmp` (emptyDir) to the StatefulSet and correct the
README — it is the only finding that breaks a core workflow in production.

## 4. Verdict

**Conditional.** The docker-compose deployment is production-usable as-is. The
documented **Kubernetes/Helm production path is not**, until these conditions are
met:

1. **Add a writable `/tmp`** (emptyDir) to the StatefulSet (or set `TMPDIR` into
   the PVC) — otherwise every upload > ~1 MB fails under
   `readOnlyRootFilesystem: true`. Correct the README claim. *(T1)*
2. **Fix training restart safety after hard-stop** — refuse a new `/train` while
   the previous training thread is still alive (or stop-check the deploy fit +
   save). *(T2)*
3. **Fix rate-limit client attribution behind the proxy** — run uvicorn with
   `--proxy-headers --forwarded-allow-ips=<proxy>` (or a trusted-XFF key func),
   so per-client throttling and share-id brute-force protection actually work.
   *(T3)*

The `:` path-escape (T4) is a one-line hardening fix and should ride along.
None of these are 🔴; all are fixable in well under a week.

## 5. Top issues (ranked by business impact)

### T1 · 🟠 High · Deployment — `readOnlyRootFilesystem` breaks all uploads > ~1 MB on Helm
- **File:** `deploy/helm/classification-api/values.yaml` L188–190; `templates/statefulset.yaml` L86–94; `README.md` L161
- **Problem:** The pod runs `readOnlyRootFilesystem: true` with only the `/data`
  PVC writable — no writable `/tmp`. Starlette buffers each multipart `UploadFile`
  in a `SpooledTemporaryFile(max_size=1 MB)` that rolls over to a real file under
  `TMPDIR` (`/tmp`) once a part exceeds 1 MB, *before* `read_upload_capped`
  (`security.py:74`) ever runs.
- **Impact:** With `maxUploadMb: 200` and an ingress body cap of `200m`, every
  real CSV/model upload triggers a `/tmp` write that fails on the read-only FS —
  `POST /datasets/import` and `POST /models/import` (the core admin workflow) are
  broken in the production Helm deploy. docker-compose is unaffected. The README
  actively reassures otherwise.
- **Fix:** Mount an `emptyDir` at `/tmp` (or set `TMPDIR` to a PVC subdir); fix
  the README. Confirm with one > 1 MB upload against a `readOnlyRootFilesystem`
  pod.

### T2 · 🟠 High · Correctness — Hard-stop abandons status but not the thread → concurrent trainings
- **File:** `app/jobs.py` L102–120 (`start` guard), L148–156 (`stop`); `app/deploy.py` L170–180; `app/registry.py` L200–233 (`save`)
- **Problem:** `stop(hard=True)` sets the stop Event, bumps the generation, and
  flips status to `idle` — but never interrupts the running thread. `should_stop()`
  is polled only *between* checkpoints; the deploy refit (`final_head.fit`,
  deploy.py:180) and the multi-minute `registry.save` have no stop check. Because
  the `start` guard is status-based (`status == "running"`) and status is now
  `idle`, a new `POST /train` is accepted while the old thread still computes.
- **Impact:** Two full trainings run concurrently — CPU/RAM oversubscription that
  defeats the `cpu_max_percent` budget and the ~1×-RAM design. If the retrain
  reuses the same `model_name`, the zombie's eventual `save` can `rmtree` the new
  run's staging dir or `os.replace` a stale bundle over the fresh one
  (last-writer-wins; `_disk_lock` prevents on-disk corruption but not a
  nondeterministic deployed model).
- **Fix:** Reject `/train` while `self._thread.is_alive()`; and/or add
  `should_stop()` checks before the deploy fit and before `save`, and make `save`
  no-op on a stale generation. Document hard-stop as "abandon status, thread
  finishes in the background."

### T3 · 🟠 High · Security/API — Rate limiting is keyed on the proxy IP
- **File:** `app/limiter.py` L18; `app/main.py` L82–83
- **Problem:** `Limiter(key_func=get_remote_address)` buckets on
  `request.client.host`, which behind the TLS-terminating reverse proxy (the
  documented topology) is the proxy's IP for every request. `X-Forwarded-For`
  is not parsed; uvicorn `--proxy-headers`/`--forwarded-allow-ips` is not set.
- **Impact:** All clients collapse into one shared bucket — per-client throttling
  does not work, one client can exhaust `predict`/`train`/`export`/`share` for
  everyone, and the stated rationale for throttling `/share/{id}` (brute-forcing
  share ids) is defeated.
- **Fix:** Run uvicorn with `--proxy-headers --forwarded-allow-ips=<proxy>` (or a
  key func reading the right-most trusted XFF entry); add a test asserting
  per-XFF keying. Do **not** blindly trust the full XFF chain.

### T4 · 🟠 High (Windows) / 🟡 (Linux) · Security — `safe_name` does not reject `:`
- **File:** `app/security.py` L57–71
- **Problem:** `safe_name` rejects `/`, `\`, `..`, leading `.`, NUL — but not `:`.
  On Windows, `PureWindowsPath(data_dir) / "D:evil.csv"` yields `"D:evil.csv"`
  (drive-relative — the base dir is discarded), and `"data.csv:hidden"` becomes an
  NTFS alternate-data-stream path. **Verified** empirically this session:
  `safe_name("D:evil.csv")` is accepted. The registry already documents this exact
  class (`registry.py:50–52`) but the awareness never reached `safe_name`.
- **Impact:** On a Windows host, an admin-key holder can write/delete outside
  `data_dir`/`models_dir` via `import`/`export`/`delete`. On the Linux production
  target `:` is an ordinary filename char — no escape there. Admin-only.
- **Fix:** Add `or ":" in name` to the rejection set (`security.py:59–66`).
  One line; aligns `safe_name` with the registry's stated intent.

### T5 · 🟠 High · Performance — Model cold-load runs on the async event loop
- **File:** `app/routes/predict.py` L107–109, L156–158, L173
- **Problem:** `_load()` (→ `registry.get()` → disk read + skops deserialize on a
  cold LRU miss) is called *synchronously* inside the `async def` handlers, before
  the `asyncio.to_thread` that offloads the predict compute. `/predict/multi`
  builds `{name: _load(name)}` inline for up to 5 models against a 2-slot cache
  (evict/reload thrash).
- **Impact:** On the single worker, a cold predict stalls the event loop for the
  whole deserialize — every concurrent request, including `/health`, parks.
- **Fix:** Move `_load` inside the `to_thread` call (or run the whole handler in
  the threadpool) so deserialization never occupies the loop.

### T6 · 🟠 High · Performance/Correctness — Long bundle save holds the disk lock
- **File:** `app/registry.py` L200–233 (`save` holds `_disk_lock` across `_write_bundle`), L235–252 (`load_fresh`/`get`)
- **Problem:** `save()` holds `_disk_lock` for the entire `_write_bundle`, which
  per the project's own memory can run tens of minutes under memory pressure (the
  documented ~53-min skops save). Any disk-touching op (`load_fresh`, `info`,
  `delete`, `export_zip`, `import_zip`) blocks for that window. A `/predict` for a
  model *not* in the 2-slot cache calls `get()` → `load_fresh()` → blocks.
- **Impact:** During a slow save, predictions for uncached models (and
  `/models/{name}`) hang for minutes though the server reports healthy.
- **Fix:** Stage into `.name.tmp` **without** the lock (the tmp name is unique and
  invisible to readers); take `_disk_lock` only for the final `os.replace` (and
  the pre-write cleanup). Reads then block only for the rename.

### T7 · 🟠 High · Correctness — Non-UTF-8 CSVs crash with 500 (German cp1252/latin-1)
- **File:** `app/data.py` L119, L139, L282; `app/routes/datasets.py` L75
- **Problem:** Every `pd.read_csv(..., encoding="utf-8")` is hard-coded with no
  fallback. A cp1252/latin-1 CSV — common for German WLO metadata exports — raises
  `UnicodeDecodeError`, which is not a `TrainingInputError`, so `/train` reports a
  generic failure and the inspection routes fall through to a sanitized 500.
  `count_rows` uses `errors="ignore"`, so a file *lists* with a correct row count
  but then fails to load — inconsistent.
- **Impact:** A user uploads a legitimate regional-encoding CSV and gets an opaque
  500 with no actionable message.
- **Fix:** Fall back to `latin-1`/`cp1252` (or `encoding_errors="replace"`), or
  detect and raise a `TrainingInputError` ("re-save as UTF-8") → 400.

### T8 · 🟡 Medium · Security — No Content-Security-Policy (feasible, scoped to `/ui`)
- **File:** `app/main.py` L86–99
- **Problem:** CSP is omitted globally "to not break the CDN-backed Swagger UI at
  `/docs`" — but `/ui` is fully self-contained (same-origin `style.css` + four
  same-origin scripts, no inline JS/CSS), so a strict CSP can be scoped to `/ui`
  exactly as `Cache-Control` already is (main.py:95). The sibling data-prep app
  does precisely this.
- **Impact:** If any `esc()`/`escP()` is ever missed, there is no second XSS layer
  (all rendering goes through `innerHTML`).
- **Fix:** Emit `Content-Security-Policy: default-src 'self'; object-src 'none';
  base-uri 'none'; frame-ancestors 'none'` on `/ui` (and API) responses; exempt
  `/docs`/`/redoc`.

### T9 · 🟡 Medium · Security/API — Unthrottled delete/enumerate + dead `rate_limit_default`
- **File:** `app/limiter.py` L18, L23–31; `app/routes/models.py` L40–69; `app/routes/datasets.py` L184–194; `app/routes/system.py` L64
- **Problem:** The limiter has `default_limits=[]`, and only predict/train/export
  routes carry `@limiter.limit`. `DELETE /models/{name}`, `DELETE /datasets/{name}`,
  `GET /models`, `GET /models/{name}`, `GET /config`, `/train/status`,
  `/train/stop` have no limit. `settings.rate_limit_default` ("120/minute") is
  resolved only for unknown names in `_resolve` and is therefore wired to nothing.
- **Impact:** Enumeration/deletion endpoints are unthrottled; an advertised
  default throttle silently does nothing.
- **Fix:** Set `default_limits=[settings.rate_limit_default]` (honoring
  `rate_limit_enabled`) or decorate the bare routes; remove or wire the dead
  config.

### T10 · 🟡 Medium · Correctness — Min-rows guard runs before rare-label row-dropping
- **File:** `app/prepare.py` L67–69 (guard on pre-filter count), L76 (`prepare_targets` drops rows), L89–92 (`three_way_split(len(texts), …)`)
- **Problem:** The "≥ 10 rows" check uses the post-cleaning count *before*
  `prepare_targets` drops rows whose only labels fell below `min_samples`. The
  count fed to `three_way_split` can be far smaller (even < 4), so with
  `val+test = 0.3` a split can yield an empty val/test; metrics then compute on an
  empty array (F1 `zero_division=0` → 0.0) and a near-empty model deploys without
  error.
- **Impact:** A "successful" training with meaningless/zero metrics instead of a
  clear rejection.
- **Fix:** Re-assert a minimum usable-row count *after* `prepare_targets` and
  raise `TrainingInputError` otherwise. *(exact boundary needs verification)*

## 6. All findings (by dimension)

### Architecture
- 🟡 `registry.py` god module — 4 responsibilities in 341 LOC (bundle codec / LRU
  cache / locked disk store / zip import-export security). Split `bundle.py` +
  `porting.py`; `Registry` keeps cache+store+locks. (violates own 300-line rule)
- 🟡 `data.py` mixes 4 concerns in 313 LOC — cleaning, row-count cache, load,
  target/split prep, and the `analyze_dataset`/`validate_dataset` inspection
  endpoints. Move inspection to `dataset_stats.py`; consider relocating
  target/split helpers next to `prepare.py`.
- 🟢 `dataset_info` reads pandas inline (datasets.py:75) instead of delegating to
  `data` — minor route-layer logic leak; also decentralizes encoding handling.

### Security
- 🟠 T4 `:` path escape (above). 🟠 T3 proxy rate-limit (above). 🟡 T8 no CSP.
  🟡 T9 unthrottled endpoints + dead default.
- 🟡 CORS `*` + hard-coded `allow_credentials=True` (main.py:101–108): if an
  operator sets `APIV3_CORS_ALLOW_ORIGINS=*`, Starlette reflects the Origin and
  allows credentialed cross-origin requests. Default empty = safe. Guard/strip `*`
  when credentials are on, or document it as unsupported.
- 🟢 `secrets.compare_digest` raises `TypeError` on a non-ASCII `X-API-Key`
  (security.py:26–28) → sanitized 500 instead of a clean 401. Guard key
  charset/type before compare.
- 🟢 `separator` query param → `pd.read_csv(sep=...)` (datasets.py:63,75): a
  multi-char value is a regex (python engine) — catastrophic-backtracking CPU
  burn. Restrict to a single character.
- 🟢 Upload safety keys on filename extension, not content-type (datasets.py:145,
  models.py:113) — acceptable (content validated downstream), noted.

### Logic & Correctness
- 🟠 T2 hard-stop concurrency. 🟠 T7 non-UTF-8 → 500. 🟡 T10 min-rows-before-drop.
- 🟡 Empty/malformed CSV → 500 on inspection routes (datasets.py `dataset_info`/
  `validate`/`analyze`; only `TrainingInputError` is mapped to 400) — wrap pandas
  reads, map `EmptyDataError`/`ParserError` → 400.
- 🟡 `save` publishes to cache outside `_disk_lock` (registry.py:219–233): a
  concurrent `delete` landing in the gap leaves a model in memory but absent on
  disk (`get` succeeds, `info` 404s until eviction). Narrow, single-worker.
  Insert into cache while still holding `_disk_lock`.
- 🟡 ShareStore non-atomic write + swallowed corruption (sharing.py:30–45): a
  crash mid-`write_text` corrupts `share_links.json`; `_load`'s broad `except`
  silently returns `{}` and the next `create()` wipes all links with no log.
  Write via tmp+`os.replace`; log a warning on discard.
- 🟢 `import_zip` returns `self.info(name)` after releasing the disk lock
  (registry.py:335): an admin `delete` in that gap makes `info` raise
  `FileNotFoundError`, uncaught in the import route → 500. Extremely narrow,
  admin-only. *(needs verification)*
- 🟢 `sweep_stale_tmp` increments `removed` even when `rmtree(ignore_errors=True)`
  fails — count can over-report. Cosmetic.
- 🟢 `use_auto_settings` (schemas.py:95–97) documented "no effect" — dead field
  retained for compatibility.

### Performance
- 🟠 T5 cold-load on event loop. 🟠 T6 save holds disk lock.
- 🟢 `import_dataset` writes up to 200 MB via `target.write_bytes` synchronously in
  an `async` route (datasets.py:156) — briefly blocks the loop. Offload or stream.
- 🟢 `/predict` JSON body bounded but large (~100 MB worst case: 1000 texts ×
  100k chars). Set a request-body cap at the proxy; consider lower practical caps.

### API
- 🟡 Inconsistent error envelope: `HTTPException` → `{"detail": str}`, 422 →
  `{"detail": [list]}`, 429 (slowapi) → `{"error": ...}`, 500 → `{"detail": ...}`.
  Register a `RateLimitExceeded` handler emitting `{"detail": ...}` to unify.
- 🟡 No `response_model` on any route (all return `-> dict`); OpenAPI shows empty
  response schemas, nothing validates output, and there is no `/v3` version path
  for a breaking change. Add response models for at least `/predict`,
  `/models/{name}`, `/train/status`, or document the plain-dict contract.
- 🟡 CSV-input errors surface as 500 (see Correctness).

### Frontend / UX
- 🟡 No CSP (T8). 🟡 `visibilitychange` listener leaks across sign-out/in
  (app.js:150–159): `startStatusPolling` guards the interval but re-adds a
  `document` listener each start; `stopStatusPolling` never removes it — each
  logout→login accumulates a listener + redundant `/train/status` polls. Register
  once at `boot()` or remove on stop.
- 🟢 Tabs use `aria-current="page"` buttons, not the WAI-ARIA tab/tabpanel pattern
  (no `role=tablist/tab/tabpanel`, `aria-controls`, arrow-key nav). Keyboard-
  operable but not announced as a tab set.
- 🟢 `/docs` (Swagger) pulls JS/CSS from jsDelivr — leaks visitor IP, contrary to
  the project's no-third-party posture. Self-host swagger assets if `/docs` is
  public. (`/ui` itself is verified CDN-free.)

### Testing
- 🟡 Process-global slowapi store shared across tests (test_api.py) — the `export`
  bucket (30/min, shared by ~9 endpoints) is never reset and two tests drop it to
  `1/minute`, risking order/speed-dependent spurious 429s. Reset
  `limiter._storage` per test or isolate the limiter tests.
- 🟡 Concurrency tests are sleep/wall-clock-coupled (test_training.py:103–125,
  339–381, 603–671) — `time.sleep`, `Event.wait(timeout)`, `assert age >= 0.2`
  can violate under CI load/GC. Drive transitions with explicit sync where
  possible; keep generous margins.
- 🟢 Micro-gaps: `/config` untested; the route-level 413 (upload-cap wiring) only
  unit-tested via `read_upload_capped`; the CORS-enabled branch untested; the 429
  body shape never asserted (would have caught the envelope inconsistency).

### Dependencies
- 🟡 Dev/tooling deps unpinned (pyproject.toml:23): `pytest>=8.0`, `ruff>=0.4`,
  `mypy>=1.9`, `httpx>=0.27` are open lower bounds with no lock — CI installs
  whatever resolves that day (a ruff/mypy bump can change gate outcomes). Add a
  `requirements-dev.lock`.
- 🟢 `test_dependency_locks.py` checks version agreement but not that
  `requirements-hashes.lock` entries actually carry `--hash=` lines — a recompile
  that dropped hashes would pass. Assert ≥1 `--hash=sha256:` per pinned line.
- 🟢 Hashes lock compiled `--python-version 3.11` while `requires-python >= 3.10`
  (pyproject) — a 3.10 deploy could need marker-gated backports absent from the
  hashed set. Raise `requires-python` to `>=3.11` or compile for the lowest
  supported version.

### Documentation
- 🟡 README (L161) claims the Helm chart's `readOnlyRootFilesystem: true` is safe
  because "all writable paths live on the PVC" — false for upload `/tmp` spooling
  (T1). Correct it and document the required `/tmp` emptyDir.

### Deployment & Ops
- 🟠 T1 read-only-FS upload break.
- 🟡 CI workflows set no top-level `permissions:` (ci.yml, docker.yml `test` job)
