Baseline: the 2026-07-16 re-audit (score 82, Conditional; every item there was
remediated the same day). This audit hunts for what changed since — the July 25/26
wave (format-2 bundles, gzip datasets, label-name repair, container-label guard,
profile ladder) — and for what the earlier audits missed. Goals stated by the owner
for this pass: fast on CPU, short training runs, shareable models, good recognition
rate, a UI that is "still very simple".

## Executive summary

The codebase is in good shape and has *improved* since July: the pipeline is cleanly
staged, every tuning decision is measured and written down, persistence is
pickle-free, the supply chain is hash-locked and CVE-free today, and 187 hermetic
tests run in 25 s. Three things need attention before anything else. **(1) The admin
UI's own Content-Security-Policy blocks every `style="width:…"` attribute, so every
confidence bar and the training progress bar render *full* regardless of value**
(verified live: a 0.004-confidence label draws a 100 % bar) — a silent
misrepresentation for the editorial audience the UI exists for. **(2) Seven weeks of
work sit uncommitted on top of a single initial commit** (54 modified + 6 untracked
files, no remote, CI has never run) — one disk failure loses the format-2 migration,
the gzip support and the label-repair work. **(3) Four of the fourteen bundles on disk
are format-1 and cannot load**, yet the API lists them and the UI shows their metrics
as if they were usable; one of them (`faecher_ai_cv5`) is the model deployed on the
vServer. The single most important action is to commit and push, then fix F1 (an
hour of work). Everything else is roadmap, not blocker — see the companion
`docs/plans/2026-09-08-ergaenzungsplan.md`.

## Overview

- **Stack:** FastAPI + uvicorn, scikit-learn TF-IDF (word + char) → OneVsRest
  LogisticRegression (newton-cg, float32), skops bundles (format 2), pydantic-settings,
  slowapi; vanilla-JS admin UI; Docker (digest-pinned) + Helm; GitHub + GitLab CI.
- **Purpose:** train metadata classifiers (subject, educational level, …) from WLO CSV
  exports on CPU, serve them via REST, move them between servers as ZIPs.
- **Size:** app 4,240 lines / 28 files; tests 3,547 lines / 13 files; UI 1,240 lines;
  scripts 2,136 lines (15 benchmark/repair tools, ruff-gated, otherwise untested except
  `enrich_tail`).
- **Read:** everything under `app/` and `app/static/ui/`, all docs, CI, Dockerfile,
  compose, Helm values/templates. Skipped: vendored `swagger-ui-bundle.js`; test bodies
  beyond fixtures/greps; benchmark scripts beyond their docstrings.
- **State on disk (not in git):** `models/` 1.4 GB (14 bundles incl. 3 `probe_*`
  experiments and 2 `.prebackup` copies), `data/` 472 MB (11 CSVs), `fertige-modelle/`
  57 MB (two exported ZIPs), `share_links.json` with 21 live links.

## Top issues (verified against source; ordered by impact)

### F1 · 🟠 Frontend — CSP blocks every inline width, all bars render full
- **Files:** `app/main.py` L152–155 (CSP for non-`/docs` routes: `default-src 'self'`,
  no `style-src`), `app/static/ui/app.js` L149 (confidence bar), L221–222 (training
  progress bar), L251 (topbar mini-bar) — all emit `style="width:…%"` via `innerHTML`.
- **Problem:** Under `default-src 'self'` a `style` *attribute* is inline style and is
  blocked. Verified live on `/ui/`: five ranked predictions with attributes
  `width:100%`, `width:0%`, `width:0%`, `width:0%`, `width:0%` all measured **171 px =
  the container width**; the console logged 80+ "Applying inline style violates …
  default-src 'self'" errors during one page visit.
- **Impact:** A 0.004-confidence label and a 1.000 label look identical; the progress
  bar shows 100 % from the first second of a training. The number next to the bar is
  right, the picture is wrong — for the non-technical audience the picture wins.
  The July re-audit's "zero CSP violations" claim never covered a rendered prediction.
- **Fix:** Keep the strict CSP. Emit `data-width="${pct}"` in the templates and apply
  widths through the CSSOM after each render (`el.style.width = …` is not governed by
  `style-src`); one 6-line helper called from the three render sites. Extend
  `test_ui_sources_contain_no_inline_event_handlers` (`tests/test_api_hardening.py`
  L144) to also reject `style="` / `` style=` `` in the UI sources so this cannot
  come back.

### O1 · 🟠 Ops — seven weeks of work uncommitted, no remote, CI never ran
- **Evidence:** `git log` = one commit `8a35685` (2026-07-16); `git status` = 54 modified
  files (+3,503 / −303) and 6 untracked (`docs/audits/2026-07-16-reaudit.md`,
  `docs/model-approach-comparison.md`, `scripts/benchmark_c_grid.py`,
  `data/label_names.json`, `char_range_results.json`, `fertige-modelle/`); `git remote
  -v` empty; `.github/workflows/ci.yml` has never executed.
- **Impact:** The format-2 bundle migration, gzip datasets, label-name repair, container
  guard, profile ladder, 65 new tests and four docs exist in exactly one place. The
  hash-locked install path (`--require-hashes`) has never been proven on a clean
  runner.
- **Fix:** Commit in logical slices (format-2 · gzip · label repair · profiles · docs ·
  tests), add a remote, push, watch the first CI run, tag `v3.1.0`. Decide
  `data/label_names.json` (commit as a dated snapshot — it is 39 KB and build-time
  reproducible) and ignore `char_range_results.json`, `fertige-modelle/`, `.claude/`.

### O3 · 🟡 Ops/API — four format-1 bundles are listed but cannot load
- **Files:** `app/model_io.py` L187–196 (format-1 → `UnsafeModelError`),
  `app/registry.py` L65–72 (`list()` = any dir with `config.json`),
  `app/static/ui/manage.js` L42–62 (table shows their metrics without a hint).
- **Evidence:** `models/bildungsstufe_ai_cv5`, `faecher_ai_cv5`, `faecher_cv5`,
  `faecher_synth_bal` have no `vocabulary.json` (checked); the UI lists all four with
  F1 values; `/predict` on them returns 422 "Model bundle is invalid or unloadable".
- **Impact:** An editor picks `faecher_ai_cv5` (the production model on the vServer)
  in the Query tab and gets an opaque 422. Warmup of such a name logs and skips.
- **Fix:** Retrain the two that matter (`faecher_ai_cv5`, `bildungsstufe_ai_cv5`) with
  `best`, delete the rest; make `registry.list()`/`info()` surface `format_version`
  and let the UI mark bundles it cannot serve (grey row + "retrain"). Also exclude
  `*.prebackup` dirs written by `scripts/prune_bundle_labels.py` L110 from
  `list()` — today they appear as models and can be predicted with (`.name.prebackup`
  would be hidden by the existing dot-prefix rule).

### S1 · 🟡 Security — dataset routes act on any file in the data dir
- **Files:** `app/routes/datasets.py` L63–87 (`dataset_info`), L177–201
  (`export_dataset` + share link), L204–216 (`delete_dataset`); `app/prepare.py` L31
  (`label_names.json` lives in the same directory).
- **Problem:** Only the *listing* filters on `.csv`/`.csv.gz` (L56). Any safe name that
  exists is served, shared and deleted: `DELETE /datasets/label_names.json` silently
  removes the authoritative display-name sidecar; a share link can expose any file
  dropped into the data volume.
- **Impact:** Admin-only, so not an exposure — but a one-line mistake in the UI or a
  script destroys the label vocabulary every future training relies on.
- **Fix:** One `_dataset_path(name)` helper that also requires the dataset suffix
  (404 otherwise); reuse in the four routes. Test: delete/export/share of
  `label_names.json` → 404.

### S2 · 🟡 Security — share links can be created but never listed or revoked
- **Files:** `app/sharing.py` L64–84 (create/resolve only), `app/routes/models.py`
  L96–98, `app/routes/datasets.py` L195–197.
- **Problem:** A share link is a bearer capability valid for up to 168 h. There is no
  `GET /share` and no `DELETE /share/{id}`; the only revocation is editing
  `share_links.json` on the volume (21 links are live on this machine right now).
- **Fix:** Admin-only list + revoke endpoints (small; the store already has the lock and
  persistence), optional `max_downloads`; the UI gets an "active links" box.

### P1 · 🟡 Performance — CV refits the vectorizer per fold
- **Files:** `app/tuning.py` L140–142 (per-fold `fit_transform`/`transform`),
  `app/deploy.py` L193–195 (deploy pass).
- **Problem:** `auto` runs 4 vectorization passes, `best` 6; the README measures one
  pass at 2.3 min for 156 k rows, so that is ~9 min of the 40-min `auto` run and
  ~14 min of `best`. The strictness buys "no IDF leakage", an unsupervised statistic
  most practitioners fit once.
- **Fix (measure first):** fit-transform once over all rows, slice the CSR matrix per
  fold, reuse it for the deploy fit. Expected saving ≈ 17 % (`auto`) / 20 % (`best`)
  wall-clock; adopt only if macro F1 moves < 0.002 on `data_30k_ai.csv` and the
  university target. Keep the strict path behind a profile flag.

### P2 · 🟢 Performance — exports and uploads are buffered in RAM
- **Files:** `app/registry.py` L202–211 (`export_zip` → `BytesIO`),
  `app/security.py` L77–96 + `app/routes/datasets.py` L170–173 (upload → bytes →
  `write_bytes`).
- **Impact:** A 179 MB bundle export or a 200 MB CSV upload is a 200 MB spike on the
  single worker; the upload write is also non-atomic (a crash leaves a truncated CSV
  that lists as a dataset).
- **Fix:** Stream the zip to a temp file and `FileResponse` it; spool uploads to
  `tmp + os.replace` (the pattern bundles and the share store already use).

### D1 · 🟡 Documentation — three drifts
- `README.md` L243: "`best` (5-fold CV, 5 `C` values reaching past both known optima)"
  contradicts the Profiles table (L165–171) and `config.yaml` (`[2, 8, 32]`).
- `README.md` L425: "152 tests (96 % line coverage)" — the suite has 187.
- `docs/configuration.md` L217–221: the `max_word_features` bullet is orphaned below
  the "Container labels" section; it belongs to the `config.yaml` list (L124–172).

### A1 · 🟢 Architecture — two files over the size guideline
- `app/data.py` 359 lines: the display-name reconciliation (L169–210,
  `_rejoin_split_names`/`_pair_names`) is a second responsibility → `app/label_names.py`.
- `tests/test_training.py` 1,501 lines: split by theme (jobs/registry/profiles/bundle).
