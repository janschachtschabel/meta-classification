## 5. Top issues (ranked by business impact)

**[🟠High] Concurrency — `save()`/`delete()` race an in-flight cold-cache `predict` (TOCTOU) — STILL OPEN**
File: `app/registry.py` — `save` L171-182 (rmtree L173/177, os.replace L178), `delete` L214-219; readers `load_fresh`/`get`/`_read_bundle` L103-127,184-200.
Problem: `self._lock` wraps only the in-memory cache dict (verified L179/191/196/215); the filesystem `rmtree`/`replace` and the three-file `_read_bundle` reads run unlocked. `/predict` runs on `to_thread`, so a reader thread and an admin `save`/`delete`/`import` thread touch the same dir concurrently.
Why/Impact: On Windows → intermittent 500; on POSIX → a **mixed bundle** (new config.json + stale head.skops) → silently wrong predictions, the hardest failure to trace. Triggered when an admin delete/import lands during a cold-cache predict of the same name.
Fix: A per-name lock around disk mutation *and* the cold-load read (or widen `_lock`). The comment L164-170 reasons only about crash-safety, not concurrent readers.

**[🟠Medium] Security/API — `/train/status` leaks raw internal exception to `readonly` callers — NEW**
File: `app/jobs.py:95` (`message=str(exc)`) → `app/routes/training.py:120,129` (`GET /train/status`, `require_role("readonly")`, returns `snapshot()`).
Problem: A failed training thread stores `str(exc)` in the job state; `/train/status` returns it verbatim to any readonly key as a **200** body — the global 500 handler doesn't cover this channel.
Why/Impact: `str(exc)` on ML/IO failures embeds absolute paths, pandas/sklearn internals, and dataset column/value fragments — recon material disclosed to the lower-privilege role. Same leak class the global-500 fix closed, different path.
Fix: Store a generic `message` ("Training failed.") and `logger.exception(exc)` server-side; gate any detail behind admin.

**[🟠Medium] Security/Deployment — No security response headers — STILL OPEN**
File: `app/main.py:64-93` (only conditional CORS; no header middleware).
Problem/Impact: No `X-Content-Type-Options: nosniff`, `X-Frame-Options`/CSP, `Referrer-Policy`, HSTS. `/docs` clickjackable; JSON MIME-sniffable; relies on an assumed proxy.
Fix: ~15-line `BaseHTTPMiddleware` setting the four headers; or make the proxy authoritative and document it.

**[🟠Medium] API/Performance — Rate-limit gaps: 14 of 22 routes uncapped; `default_limit` dead — STILL OPEN**
File: uncapped `analyze`/`validate`/`dataset_info`/`list`/deletes (`datasets.py:38,56,84,103,177`; `models.py:41,47,61`), `train/status`+`stop` (`training.py:120,133`), `config` (`system.py:21`); dead `limiter.py:18,46-47` (`default_limits=[]`, `default_limit` 0 call sites).
Problem/Impact: `analyze`/`validate` run a full `pandas.read_csv` + per-row clean over up to 200 MB with no throttle; a leaked admin key (or burst) pins the single worker. `rate_limit_default` is inert.
Fix: `Limiter(default_limits=[settings.rate_limit_default])` (dynamic), or decorate the heavy endpoints; either way *use* `default_limit`.

**[🟡Medium] Correctness/Statistics — CV mode double-dip metric optimism — NEW (in the new CV code)**
File: `app/tuning.py:112-119` (`cross_val_evaluate`).
Problem: `best_c` (argmax over c_grid) **and** per-label thresholds (argmax over 19 cutoffs, independently per label) are both fit on the **same OOF** that's then reported as `metrics`. The docstring (L86-90) discloses "mild in-sample optimism," but the **per-label** threshold tuning on rare labels is more than mild.
Why/Impact: CV-mode `f1_macro` and especially `per_label_f1` over-state what the deployed 100%-data model achieves on unseen input; comparing CV-mode vs split-mode numbers compares an in-sample-tuned score against a held-out one.
Fix: Nest threshold/C selection inside folds (inner OOF) or reserve one fold for reporting; cheapest: surface the per-label caveat in the returned metadata (the `evaluation` string hints OOF but not the tuning optimism).

**[🟡Low] API/Logic — `_load` maps only `UnsafeModelError`; a TOCTOU-missing model → unsanitized 500 (should be 404) — NEW**
File: `app/routes/predict.py:19-29`. `registry.get()` can raise `FileNotFoundError` (deleted between `exists()` L22 and `get()` L25) → falls to the global 500 (sanitized, but wrong code).
Fix: Also catch `FileNotFoundError` → 404, matching `model_info`/`export_model`.

**[🟡Low] Security — Zip-bomb guard trusts the archive's declared size — STILL OPEN**
File: `app/registry.py:248-253` (sums attacker-controlled `info.file_size`) vs L260-261 (`archive.read(member)` inflates unbounded). Admin-only + rate-limited + 200 MB cap mitigate. Fix: bound *bytes actually read* via chunked `archive.open`.

**[🟢Low→structural] Maintainability — `training.py` crossed the 300-line cap (363), two responsibilities — COMPOUNDING**
File: `app/training.py:1-363`. The CV addition pushed it past the cap (was 311 at last audit). Clean seam: extract fit/evaluate/deploy (`_Fitted`, `_select_on_split`, `_fit_evaluate_deploy`, `_build_metadata`, `_sparse_mb`) into `app/deploy.py`, leaving `_prepare` + `run_training` (~180 lines). Behavior-preserving.

**[🟡Medium] Architecture — `_explain` ML logic in the route layer — STILL OPEN**
File: `app/routes/predict.py:111-142`. Full leave-one-out word-importance in the HTTP layer; move to `ClassifierModel.explain()`.

**[🟢Low] CORS credentials+wildcard footgun — STILL OPEN** (`main.py:79-86`, `allow_credentials=True` + `["*"]` methods/headers; origins are a strict allowlist, so latent). API keys don't need credentials → set `allow_credentials=False`.
