# api_v3 — Whole-Codebase Audit

**Date:** 2026-07-06 · **Scope:** full (all 12 dimensions) · **Method:** Standard + line-by-line on high-risk modules (auth, skops persistence, sharing, routes) · **Mode:** read-only assessment.

Conducted across four specialist lenses (Security/API, Architecture/Maintainability, Correctness/Performance/Concurrency, Testing/Deps/Docs/Ops) plus independent verification of the security-critical files and dependency/CVE scanners (`pip-audit`, `ruff`, `mypy`).

---

## 1. Executive summary

api_v3 is a **well-built, deliberately security-hardened** text-classification service: the pickle-RCE class is genuinely neutralised (skops untrusted-type gate, empirically confirmed), path-traversal/zip-slip/zip-bomb/timing are all handled, auth is enforced on every route with a fail-secure default, and there is no SSRF surface. The code is clean, small-filed, and its comments explain *why*. This is above the median for a service of its size.

The top three risks are: **(1)** a shipped dependency with 5 known CVEs on a live upload path (`python-multipart 0.0.22`); **(2)** the CI publishes the Docker image **without** gating on the test suite, so a failing build can become the deployable `:main` image; and **(3)** a single authenticated `/predict` call can exhaust the single worker's RAM/CPU because request input size is unbounded. The single most important action: **bump `python-multipart` to ≥0.0.31 and add a `needs:` edge so the image build depends on the test gate** — both are minutes of work and close a live-shipping risk.

Verdict: **Conditional** production-ready — the foundation is sound; a short, specific fix list (below) clears it.

## 2. Overview

- **Stack:** Python ≥3.10 · FastAPI + uvicorn · scikit-learn (sparse float32 TF-IDF word+char + OneVsRest LogisticRegression, `newton-cg`) · skops (pickle-free persistence) · pydantic-settings (`APIV3_` env prefix) · slowapi (in-memory rate limit). Single-worker by design (job/LRU-cache/limiter are process-local; CPU work via `asyncio.to_thread`).
- **Purpose:** train and serve metadata text classifiers; manage datasets/models; export/import + expiring share links; all torch-free, CPU-only, low-RAM.
- **Size:** 3,098 LOC (≈2,533 `app/` + ≈565 `tests/`), 20 app modules + 5 route modules, all ≤311 lines. 31 tests. Full ops stack: Dockerfile, docker-compose, Helm chart, GitHub + GitLab CI.
- **Covered:** every `app/*.py` and `app/routes/*.py` read (most line-by-line); all `tests/*`; `pyproject.toml`, `requirements.lock/.txt`, `README.md`, both `CLAUDE.md`, `Dockerfile`, `docker-compose.yml`, full Helm chart, `.github/workflows/*`, `.gitlab-ci.yml`, `config.yaml`, `.env.example`. Scanners run: `pip-audit`, `ruff`, `mypy`.
- **Not covered / caveats:** cyclomatic-complexity figures are eyeball estimates (no `radon` run — flagged where relevant); `vulture` unavailable (dead-code found manually); the workspace is **not under git**, so what is actually tracked vs ignored is unverifiable until migration (large artifacts `models/…` ~224 MB and `data/data_30k.csv` ~80 MB are excluded by `.gitignore`/`.dockerignore`, but this can only be confirmed under git); reverse-proxy TLS/security-header assumptions and slowapi-behind-proxy behaviour are deploy-dependent and unverified here.

## 4. Verdict — **Conditional**

The security and architecture foundations are genuinely strong; nothing here is a rewrite. Ship once these conditions are met:

1. **Bump `python-multipart` to ≥0.0.31** in `requirements.lock` (live CVEs on the upload path).
2. **Gate the Docker publish on CI** (`docker.yml` must depend on ruff+mypy+pytest passing).
3. **Bound `/predict` input** (list length + per-text length) to remove the single-request DoS.
4. **Fix the predict error contract**: map `UnsafeModelError`/load failures to a clean 4xx and add a global exception handler (no raw 500 bodies).
5. **Decide the share-link authz model** (bearer capability *or* role-scoped — currently a `readonly` key can redeem any live link and exfiltrate datasets).

Items 1–2 are minutes; 3–4 are small, well-scoped changes; 5 is a short design decision. The concurrency race (#5 in Top issues) and the cancellation test gap should follow in the same cycle.

## 5. Top issues (ranked by business impact)

**[🟠High] Dependencies — `python-multipart 0.0.22` ships with 5 known CVEs**
File: `requirements.lock:8`
Problem: Pinned `python-multipart==0.0.22`; `pip-audit` reports CVE-2026-40347/-42561/-53538/-53539/-53540 (fixed 0.0.26–0.0.31). It parses multipart uploads on `POST /models/import` and `POST /datasets/import`.
Why: CI (`ci.yml`) and Docker (`Dockerfile`) install with `-c requirements.lock`, so the vulnerable version is exactly what ships. A newer version in the dev's global env masks it locally.
Impact: Deployed image carries a multipart parser with published DoS/parsing CVEs on an exposed (admin) upload path.
Fix: `python-multipart==0.0.31` in `requirements.lock`; the `>=0.0.9` floor in `pyproject.toml`/`requirements.txt` already permits it. Re-run ruff/mypy/pytest.

**[🟠High] Deployment — Docker image is built & pushed independently of the test gate**
File: `.github/workflows/docker.yml:9-15, 74-85`
Problem: `docker.yml` triggers on push to `main` and pushes to GHCR with no `needs:`/`workflow_run` dependency on `ci.yml` (ruff/mypy/pytest). The two workflows run in parallel and unlinked.
Why: A commit whose tests fail still publishes `:main`/`:sha-…`. (GitLab is fine — `build` is a later *stage* than `test`; only the GitHub path is ungated.)
Impact: Broken/untested code can become the deployable image consumers pull.
Fix: Add a prerequisite job (`needs: [api]`) in `docker.yml`, or trigger via `workflow_run` on CI success.

**[🟠High] Performance/Security — `POST /predict` accepts an unbounded `texts` list (single-request DoS)**
File: `app/schemas.py:62-68` → `app/routes/predict.py:33-45` → `app/classifier.py:88-112`
Problem: `texts: list[str]` has no `max_length` and elements no length cap; `predict` builds `len(texts) × len(classes)` `Prediction` objects and sorts per row. Rate limiting counts requests, not payload.
Why: One authenticated `readonly` request can post millions of strings / huge strings; the whole request is materialised in RAM and CPU-bound work runs on a `to_thread` worker.
Impact: Trivial memory/CPU exhaustion of the single worker from one request.
Fix: `Field(min_length=1, max_length=N)` on `texts` (e.g. 1000), element-wise length cap (e.g. 100 000 chars), and bound `top_k` (`ge=0, le=1000`). Consider an ASGI/proxy body-size limit.

**[🟠High] Security/API — Uncaught `UnsafeModelError`/load failures on `/predict` → 500 + no global handler**
File: `app/routes/predict.py:19-24, 58-61` · `app/main.py:56-84`
Problem: `_load` → `registry.get` → `_read_bundle`/`_safe_skops_load` can raise `UnsafeModelError`/`KeyError`/`ValueError` for a corrupt or version-drifted bundle; predict catches only `FileNotFoundError`. No app-level `Exception` handler exists (only `RateLimitExceeded`).
Why: A `readonly` caller naming a broken model gets an unstructured 500; with any verbose ASGI/proxy config the exception string can leak; the `{detail: …}` contract breaks.
Impact: Inconsistent error envelope + potential internal-detail disclosure, triggerable by a low-privilege caller.
Fix: Map load failures to `HTTPException(422, "Model bundle is invalid or unloadable.")` (mirror `models.py:126`); register a global handler that logs server-side and returns `JSONResponse(500, {"detail": "Internal server error."})`.

**[🟠High] Concurrency — `save()`/`delete()` race an in-flight cold-cache `predict` on the same model dir**
File: `app/registry.py:152-171, 203-208` (readers at 173-189, 92-116)
Problem: `save`/`delete` do `shutil.rmtree`/`os.replace` on the model directory holding the lock only for the *cache* mutation; a concurrent cache-miss `predict` runs `load_fresh`→`_read_bundle` reading the same files with no lock.
Why: TOCTOU across `to_thread` worker threads. On Windows `rmtree`/`replace` on an open file raises; on POSIX the reader can observe a mixed set (new `config.json`, stale `head.skops`).
Impact: Intermittent 500s, or a **silently mismatched model** (config vs head from different bundles) when an admin delete/import lands during a cold-cache predict of the same name.
Fix: Serialise disk mutation and disk read of the same name under a per-name lock (or extend `self._lock` scope), or load into a temp handle and swap atomically. The existing comment (156-158) reasons only about crash-safety, not concurrent readers.

**[🟡Medium] Security — Share-link authorization is coarse (readonly key redeems any live link)**
File: `app/routes/models.py:131-152` · `app/sharing.py:47-67`
Problem: `GET /share/{id}` requires only `readonly` and binds the link to neither creator nor redeeming key. So the 96-bit id is not a standalone capability (auth is still required), yet any holder of the org's `readonly` key can redeem *any* live share id — including full dataset CSVs — with no revocation/audit.
Why: The design is ambiguous: either the link is the capability (then no auth) or auth is (then the link adds little). As built, `readonly` is silently escalated to "export anything anyone ever shared."
Impact: A classification-only key can exfiltrate complete datasets/models.
Fix: Pick a model — drop `require_role` on `/share/{id}` (id is the bearer secret, document it), or store creator/role on the link and scope redemption (gate dataset shares behind admin). Add link revocation.

**[🟠High] Testing — Job cancellation (`/train/stop`, cooperative `should_stop`) is entirely untested**
File: `tests/test_training.py` (absence) · route `app/routes/training.py:132-141` · logic `app/jobs.py:88-105`
Problem: Every `run_training` test passes `should_stop=lambda: False`. Nothing covers the mid-run `return None` checkpoints, the "returns `{}` if cancelled" contract, `status="stopped"`, or `hard=true` → `idle`.
Why: `/train/stop` is an advertised critical path and the cooperative-stop is a headline feature; a regression ignoring the stop event ships green.
Impact: Cancellation can silently rot — an uncancellable/stuck job in prod is exactly what the feature prevents.
Fix: Add a test with a `should_stop` that flips True after the first progress callback, asserting `{}` result + no bundle written; add a `TrainingJob` state-transition test for `stopped` and `hard` reset.

**[🟡Medium] Security/API — Heavy endpoints uncapped; `rate_limit_default` is dead**
File: `app/limiter.py:18, 46-47` · `app/routes/datasets.py:83-120` · `app/routes/models.py:60` · `app/routes/training.py:119`
Problem: Only predict/train/export carry `@limiter.limit`. `POST /datasets/analyze` + `/validate` (full `pandas.read_csv` + label scan over up-to-200 MB), the DELETEs, `GET /train/status`, `GET /datasets/{name}` (full line-count + pandas read), `GET /config` are uncapped. `Limiter(default_limits=[])` + unused `default_limit()` mean `settings.rate_limit_default` is inert.
Why: `analyze`/`validate` are CPU/IO-heavy over attacker-influenced sizes; a leaked key drives load with no throttle.
Impact: Resource-exhaustion/cost-amplification on the heaviest endpoints.
Fix: Set `default_limits=[default_limit]` on the `Limiter`, or decorate `analyze`/`validate`/deletes/status/list. At minimum cap the two CSV-scanning endpoints.

**[🟢Low→latent-High] Security — `_safe_skops_load` passes `trusted=untrusted` (safe only by the empty-allowlist coincidence)**
File: `app/registry.py:59-64`
Problem: `skops_load(..., trusted=untrusted)` is reached only when `disallowed` is empty; because `_ALLOWED_EXTRA_TYPES` is empty, `untrusted` is then `[]`, so effectively `trusted=[]`. **Safe today** (verified). But if anyone ever populates `_ALLOWED_EXTRA_TYPES`, this line would pass the *actually-untrusted* discovered types straight into `trusted=`, trusting exactly what it just flagged — re-opening the RCE class the module exists to prevent.
Why: The variable name inverts the intent; correctness depends on an invariant a future edit can silently break.
Impact: None now; a latent landmine that could regress into import-time code execution.
Fix: `skops_load(str(path), trusted=sorted(_ALLOWED_EXTRA_TYPES))` — identical now, safe under future allowlist changes; add a comment stating the invariant. (Cheap insurance; listed high for visibility despite low current severity.)

**[🟡Medium] Performance — Model deserialization (`_load`) runs on the event loop, not a thread**
File: `app/routes/predict.py:19-24, 58-61, 102-103`
Problem: `_predict`/`_explain` call `_load(model_name)` *before* `asyncio.to_thread(...)`. On a cache miss this runs `skops_load` of head+vectorizer synchronously on the event loop.
Why: Only inference is offloaded; the potentially-slow deserialization blocks the loop, stalling all concurrent requests (incl. `/health`).
Impact: A cold-cache `/predict` (e.g. right after LRU eviction, `max_models_in_memory=2`) freezes the single-worker loop for the load duration.
Fix: `await asyncio.to_thread(_load, …)` or move `_load` inside the offloaded call.

## 6. All findings by dimension

### Architecture
- 🟡 `_explain` implements the full leave-one-out word-importance algorithm in the HTTP layer — `routes/predict.py:106-137` (also response-shaping policy at 27-55). Move to `ClassifierModel.explain()` / an `explain` core module.
- 🟡 Function-local `import pandas` + direct `read_csv` + a hand-rolled "lines-minus-header" row-counter duplicated in `routes/datasets.py:49-51, 66, 73-74`. Data logic belongs in `data.py` (`sample_rows`, `count_rows`).
- 🟡 `_prepare` interleaves ~5 responsibilities in ~69 lines, est. cyclomatic ~10-12 (**needs `radon` to confirm**) — `training.py:77-145`. Split into `_load_and_clean`/`_build_targets`/`_split_and_prune`.
- 🟢 `training.py` = 311 lines, over the stated ~300 cap (CLAUDE.md drift) — extract `_build_metadata` (233-263).
- 🟢 `separator` vs `csv_separator` naming for one concept across `data.py`/`schemas.py`/routes — pick one.
- 🟢 Magic numbers `200`/`60`/`5` in `routes/predict.py:39, 117, 122`.

### Security
- (Top issues: predict-500 + no global handler, share-link authz, `trusted=untrusted` landmine.)
- 🟡 No security headers (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, CSP for `/docs`) — `main.py:56-84`. Pick a layer (app middleware or documented required proxy) and make it authoritative.
- 🟢 `analyze_dataset` returns absolute server path `"file": str(path)` — `data.py:223-224` (via `datasets.py:96`). Return `path.name`.
- 🟢 CORS `allow_credentials=True` + `allow_methods/headers=["*"]`; footgun if an operator sets `APIV3_CORS_ALLOW_ORIGINS=*` — `main.py:70-77`. Reject a literal `*` when credentials on.
- 🟢 Zip-bomb guard trusts declared `info.file_size` (attacker-controlled), not measured extraction — `registry.py:228-251`. Admin-only + rate-limited mitigates; enforce the cap during extraction for robustness.
- ❔ **Needs verification:** slowapi keys on `get_remote_address` (`limiter.py:18`); behind a proxy without correct `X-Forwarded-For` handling, all clients may share one bucket (or the key is spoofable). Verify against the deployment.

### Logic & Correctness
- (Top issue: save/delete-vs-load race.)
- 🟡 `select_c` returns `best_head=None` for an **empty `C_grid`** (misconfigured `config.yaml`) → `head.predict_proba` on `None` → opaque `AttributeError` job error — `tuning.py:38-53` → `training.py:187-213`. Raise `ValueError("empty C grid")`; the cancel-path None is currently safe via the caller's re-check but relies on ordering.
- 🟡 `texts=[]` passes validation → degenerate empty 200 or library-dependent 500 — `schemas.py:63`, `classifier.py:95-99`. Fix via `min_length=1`.
- 🟡 Text that cleans to `""` (pure markup) → all-zero row → confident-looking "no labels" with no signal; training filters short texts but predict has no equivalent guard — `classifier.py:67-68`, `data.py:130-144`.
- 🟢 `top_k=0` always means "auto" regardless of `use_auto_settings`; `applied_settings.auto_mode` can misreport — `routes/predict.py:27-30, 52`.
- 🟢 `zip(..., strict=False)` on alignment-critical pairs (texts↔row_keep, classes↔masks) silently truncates a length mismatch — `data.py:116-117, 120-124, 134, 180`. Use `strict=True` except on the genuinely-ragged DISPLAYNAME zip.
- 🟢 Malformed CSV / wrong separator / non-UTF-8 surfaces as a raw pandas error → 500 on `analyze`/`validate` (routes don't wrap `data_mod` calls) — `data.py:92-110`, `routes/datasets.py:96, 118`. Catch and re-raise as a clear `ValueError`.
- 🟢 `ThreadPoolExecutor` in `vectorizers.fit`/`fit_transform` doesn't cancel the sibling on first exception (slow-fail, secondary exception swallowed) — `vectorizers.py:65-68, 86-90`. Low priority.
- 🟢 `stop(hard=True)` idle-write can race a completing runner's terminal write (locked, so no corruption, but status may not reflect intent); ETA swings on coarse phase jumps — `jobs.py:45-55, 86-105`.

### Performance
- (Top issues: unbounded `/predict`, `_load` on event loop.)
- 🟢 `set(classes)` rebuilt per item in a comprehension (`training.py:144`); `predict` rebuilds all `len(texts)×len(classes)` `Prediction`s + sorts per row even for `single`/small `top_k` (`classifier.py:100-105`). Hoist the set; use `argmax`/`argpartition` for the single/top-k cases.

### API
- (Covered under Security: error contract, rate-limit gaps, input bounds, share semantics.) The positive: correct status codes (404/409/413/400), auth on every route, OpenAPI tags/descriptions accurate.

### Testing
- (Top issue: cancellation untested.)

- 🟡 Resolve-time link expiry (`sharing.py:63-66`, distinct from the tested `_load` purge) and `read_upload_capped` 413 over-limit (`security.py:83-84`) untested.
- 🟡 `security.safe_name` has no direct unit test — only `..` via one route; leading-dot/backslash/NUL/empty branches uncovered. Add a parametrized unit test.

### Maintainability
